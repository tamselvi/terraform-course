Terraform basic 2: remote state—terraform state
+++++++++++++++++++++++++++++++++++++++++++++
--tf keeps the REMOTE STATE of the infra
--it stores it in a file called terraform.tfstate
--there is also a backup of the previous state in terraform.tfstate.backup
--when u execute terraform-apply, a new terraform.tfstate and backup is written to disk.this is how tf keeps track of remote state.
--if remote state changes and u hit terraform apply agin , tf will make change to meet the correct rmote state aging ex:: u terminate an instance that is managed by tf ,after tf apply it will start again.
--u can keep terraform.tfstate in version control ex ::git
--it gives u a history of ur terraform.tfstate file (json)
--it allows u to collaborate with other team members::unfortunately u can get conflict when 2 ppl work at same time
--local state work well in the start but when u project becomes gig, u might want to store ur state remote .
--remote state—
--terraform state can be saved rempte , using backend functionality in terraform
--the default is local terraform backend (the local terraform state file)
--other backends include,
	s3(with locking mechanism using dynamoDB)
	consul(with locking)
	terraform enterprise(the commercial solution)
--usinf the backend function has much benefit
--workimng in team : it allows for collaboration . the rmote state will always be available for whole team.
--the state file in not stored locally . possible sensitive information is now stored in remote state
--some backend will enable remote opertions. The terraform apply will then run completely remote . there sre called the enhanced backends then run completely remote. There are called enhanced backends refer the link
https://www.terraform.io/docs/backends/types/index.html
in demo , local storage 
there are 2 steps to configure a remote state
•	Add the backend code to a .tf file
•	Run the initialization process
To config a consul remote store , u can add a file backend.tf with the following contents:
Terraform {
     Backend”consul” {
          Address = “demo.consul.io”   #hostname of consul cluster
          Path = “terraform/myproject”
}}
U can also store ur state in s3—this may be commonly used

           Key = “terraform/myproject”
           Region = “eu-west-1”    }}

Above table we are mentioning 1stline data mytemplate and in 2nd line we are referring to script that script .see script mention in 1st task.

QUIZ 
1.	What is the difference between a variable and a datasource?
ANS: variables are static and datasource are dynamic
If you need dynamic information, you can use datasources instead of variables. Datasources will pull their information from a remote API before it turns into a variable that can be used in *.tf files
2.	What is local provisioning?
ANS: a shell script be executed locally on the host where terraform apply is running.
3.	Where does terraform by default saves its remote state?
ANS: terraform.tfstate
4.	What happens when terraform.tfstate is removed?
ANS: tf will not know the remote state anymore , u will have to manually recreate the terraform.tfstate
At the time of writing, terraform doesn't recreate the terraform tfstate file itself automatically. You can use terraform import to manually recreate the terraform.tfstate.
5.	What happens if 2 people are working on the same infrastructure with terraform using a git repository (e.g. github), but not sharing the terraform.tfstate?
ANS: terraform might give errors when trying to create or change infrastructure , because tf dosent know the remote state of  other person.
You'll need to share the terraform.tfvars using consul or S3 to enable collaboration
6.	what happens if you use S3 as a remote state repository for your terraform.tfstate and 2 people at the same time use terraform apply
7.	ANS: terraform can do locking to avoid situation like this but only if u enable it.
You can enable S3 locking using dynamoDB

8.	which one is not an example of a datasource?
ANS: Aws access id
9.	which are an example of datasource?
ANS: aws available ami’s//aws availability zones//aw sip address per region

5.	How many availability zones can you define for one aws_subnet resource?
ANS: just one
For every subnet you can only define one availability zone. One IP range (a subnet) can only be assigned to 1 availability zone

10.	        gateway_id = "${aws_internet_gateway.main-gw.id}"
11.	    }

ANS: public subnet will be unable to route traffic to the internet.
You want to run a database that only needs to be reachable from a webserver within the same availability zone (us-east-1b) and within the same VPC. You also want to update your database now and then. The binaries that the database server needs to download (the updates) are present on an other webserver, still within the same VPC, but on a subnet within another availability zone (us-east-1c). The webserver serves traffic for internet users.
•	 
You put the webserver in a public subnet and the database server in a private subnet. The database server will always be able to connect to the download server, as long as firewall rules are not blocking ports.
